How the Lantern factory runs

Claude sessions write the code. A wall of automated checks (the oracle) decides whether it works. The risk tier of the files touched decides who merges. You spend your time where it counts most: approving the issue, approving the plan, and reading the risky diffs.

You (the maintainer) Claude (routines and cloud sessions) GitHub Actions (no model, or run from main)

Risk tiers decide your review

The labeller picks the tier from the paths changed, using .github/tiers.yml on main. The highest tier any file reaches wins, so one risky file makes the whole PR tier 2. Nobody can relabel from inside the PR.

tier:0 · dark lane
Paths
docs/**, README.md, newly added tests/fixtures/**
Gate
Required checks green, then GitHub auto-merges.
You: nothing per PR. Read the weekly digest.
tier:1 · skim
Paths
Most of src/ and ui/: retro looks, internal pages, toolbar commands, settings, dial-up. Factory docs. Dependabot uses: bumps.
Gate
Green CI, then your look.
You: check the plan, screenshots and test changes, skim the code, merge. Run the black-box test if users will see it.
tier:2 · full review
Paths
client.rs, commands.rs, util.rs, main.rs, sandbox, Cargo.toml/lock, all of .github/, tools/blackbox/, hooks, release scripts
Gate
/security-review, claude-review.yml, black-box test.
You: start both workflows, approve their environment, read every line, merge. Never auto-merged.
Your controls

Where you act, and what each action does

GitHub · Issues

Set direction

  • File issues with the templates. Write acceptance criteria as things a user would see.
  • Add factory:ready to start the plan routine. Nobody else's label counts.
  • Reply "approved" (or "approved with: …") to the Plan comment, or correct it.
  • Answer anything tagged factory:needs-human.
Claude · cloud session

Start the build

  • After approving a plan, open a session on this repo and ask it to implement issue #N. The factory-issue skill takes it from there.
  • Use TheBrowserCloudEnvironment so CEF is already installed.
  • Check /usage weekly. Everything shares your Pro budget.
GitHub · Actions

Spend your token deliberately

  • Run workflow on claude-review.yml or blackbox.yml with the PR number. They run from main, so a PR can't rewrite them.
  • Approve the review, blackbox or oracle environment when GitHub asks.
GitHub · Pull requests

Decide what ships

  • Merge tier 1 and tier 2 PRs yourself, with a merge commit, once CI is green on the current head.
  • Claude never merges unless you ask it to.
  • To release, merge a version-bump PR (the release skill).
